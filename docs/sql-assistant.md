# 数据库助手：调用次数与 SQL 质量改进

## 原因

原流程把数据库助手作为自由调用工具的子 Agent：列表、读取前 100 行、生成 SQL、再把长 CSV 交给主模型整理。主模型把预览或省略的内容误认为数据缺失，反复委派“查询剩余记录”，每次又重新发现结构。新的子任务描述没有保留原始阈值和排序，出现 `>100` 变成 `>0`、库存升序变成 ID 排序或总库存降序等漂移。

## 已完成清单

- [x] 保留原始需求：主执行入口为本次运行绑定独立 `DatabaseRun`，子助手读取原问题，不依赖主模型缩写的委派描述；结束后清理上下文。
- [x] 减少查表：字段结构按连接配置缓存 5 分钟，不读取前 100 行业务样例。业务查询结果只在同一运行内复用，跨任务重新查询。
- [x] 固定查询口径：一次结构化提取表、字段、关联、WHERE、GROUP BY、HAVING、排序和明确指定的条数。药品库存的明确阈值、比较符、库存排序和要求返回的字段另行对照原文检查。
- [x] 拦截错误 SQL：使用 SQLGlot 语法树校验真实字段、筛选、关联类型、分组、排序、去重及 LIMIT；只允许一条受支持的 SELECT。SQL 不通过时最多修正一次，固定口径不会在纠错中被改写。
- [x] 防止重复查询：同一运行的并发或再次委派通过锁复用已有结果；失败也停止自动重查。
- [x] 保留真实结果：程序按实际返回行数核验条数，保存正确转义的 UTF-8 CSV，只给模型前 10 行预览。直接取数的最终表格由程序生成，避免模型漏行、改数或声称过期日期不存在。
- [x] 控制查询成本：连接超时 8 秒，SELECT 执行上限 10 秒，取数最多 10001 行以检测截断；超过 10000 行时标记部分结果，要求缩小范围，不估算总数。
- [x] 接入主 Agent 和文件交付：数据库助手使用有界 Runnable；补充主提示词及 sql-analytics 方法说明，原始 CSV 加入最终 artifacts，使用会话目录校验并去重。

## 验证（2026-10-14）

回归覆盖库存 99/100/101 的边界、漏 WHERE、阈值变化、比较符变化、排序反转、字段缺失、关联类型变化、明细误改聚合、任意 LIMIT、多语句、聚合别名、一次纠错、并发复用、结构缓存及主 Agent 结果交付。

完整后端回归为 669 项通过、4 项跳过；修复 CSV 引用去重并补充路径形式用例后，最新专项回归 53 项全部通过。前端已核对实际渲染 150 条表格明细，含过期日期，并显示 1 个可下载 CSV。

本机真实 SQL 返回 150 条，条件、排序和所有必需字段通过。首次结构读取约 967 毫秒，同进程缓存读取约 0.05 毫秒；连接、查询及取数约 613 毫秒。该测量不能代表大表或并发负载的性能。

经用户明确允许向配置的 `api.deepseek.com` 发送表结构及前 10 条库存预览后，原始药品问题真实端到端执行约 26.32 秒：委派 1 次、结构读取 1 次、业务 SQL 1 次；最终表格和 CSV 各含 150 条明细。逐条比较药品名、库存、批次、仓库和过期日期，与直接查询一致。已纠正此前完整列表和过期日期输出问题。

## 使用及边界

重启后端即可使用新助手；当前开发模式已自动加载。新环境通过 `uv sync` 或项目 requirements 安装 SQLGlot。提交问题时明确“批次库存”或“药品总库存”，列出返回字段及排序。结果超过 10000 条时缩小筛选范围或按业务范围分批请求。

当前校验支持单层 SELECT、JOIN、GROUP BY 和 HAVING；子查询、CTE、窗口函数、自定义函数以及多个独立查询会停止或请求澄清，不能绕过校验执行。一般自然语言的业务口径仍由模型理解，语法树检查不等于所有问题的语义正确率为 100%。本次没有修改数据库账号权限；生产部署仍应使用受限的只读账号。
